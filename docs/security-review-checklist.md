# Security review checklist (pre-deploy gate)

Complete this list before the first production deploy and again after any change to authentication, OAuth, token crypto, action endpoints or infrastructure. It mirrors the controls in the design spec, section 7. Every item names its evidence: a test, a command, or a setting.

`CF` below means `./app/node_modules/.bin/cf`. Record the result at the end and keep it outside the repository if it contains environment details.

## Automated gates

- [ ] CI green on the commit: lint (ESLint plus `scripts/check-text.ts`), format, typecheck, script tests, `pnpm test`, build.
- [ ] CodeQL (`javascript-typescript` and `actions`) shows no open alerts.
- [ ] Dependabot shows no open security alerts; `pnpm-lock.yaml` is committed and every version in `package.json` files is exact.
- [ ] A `security-review` agent pass over token handling, OAuth, Access verification and the action endpoints is done and every finding is fixed or accepted in writing.

## App access

- [ ] Access application covers **All traffic** of the Worker (including `workers.dev`); its only Allow rule is the owner's email. Evidence: Zero Trust > Access controls > Applications.
- [ ] `curl -sI https://clearbox.<subdomain>.workers.dev/api/me` returns a redirect to Access, never Clearbox JSON.
- [ ] Worker JWT verification tests pass: missing token, bad signature, wrong `aud`, wrong `iss`, expired, wrong email, service token without email (`app/test/worker/access/access.test.ts`).
- [ ] Fail-closed tests pass: missing or malformed `OWNER_EMAIL`, `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `TOKEN_ENC_KEY` or `STATE_SIGNING_KEY` gives `500 access_misconfigured` (`app/test/worker/access/access.test.ts` and `app/test/worker/access/config.test.ts`).
- [ ] Dev bypass tests pass: honored only in development mode on `localhost` / `127.0.0.1`; `DEV_AUTH_BYPASS=true` elsewhere fails closed. `app/cloudflare.config.ts` derives it from the build mode.

## OAuth

- [ ] Scopes are exactly `gmail.modify` (Google) and `offline_access User.Read Mail.ReadWrite` (Microsoft) (`GOOGLE_SCOPES`, `MICROSOFT_SCOPES` in `packages/core/src/providers/oauth.ts`). `git grep -n '"https://mail.google.com/"' -- packages app/src` (the full-access scope) returns nothing.
- [ ] Granted scopes are checked on connect (`scope_missing` case in `app/test/worker/oauth/oauth-routes.test.ts`).
- [ ] PKCE S256 and the HMAC-signed `__Host-clearbox_oauth` cookie: tampered, expired, provider-mismatch and state-mismatch tests pass (`app/test/worker/oauth/state-cookie.test.ts`, `app/test/worker/oauth/oauth-routes.test.ts`, `app/test/worker/crypto/pkce.test.ts`); the cookie is cleared on every callback.
- [ ] Redirect URIs in Google and Entra are exactly `https://clearbox.<subdomain>.workers.dev/oauth/<provider>/callback` (plus optional localhost); Microsoft uses the Web platform, not SPA.
- [ ] Google consent screen is **In production**; Entra app is multitenant plus personal accounts.

## Tokens and secrets

- [ ] AES-256-GCM round trip and AAD mismatch tests pass (`app/test/worker/crypto/aead.test.ts`).
- [ ] Microsoft refresh-token rotation is persisted, including on the failure path (`app/test/worker/oauth/token-source.test.ts`, `app/test/worker/tick/tick-tokens.test.ts`).
- [ ] `$CF workers secrets list --worker clearbox` lists all 12 secrets from contracts 3.7.
- [ ] `TOKEN_ENC_KEY` and `STATE_SIGNING_KEY` were generated by `pnpm setup:cf` or `pnpm gen-key`, not copied from tests or docs.
- [ ] No secret in the repository: `pnpm lint` passes and `git ls-files | grep -E '(^|/)\.dev\.vars$|clearbox\.local\.json|\.secrets\.json$|^eval/private/'` prints nothing.

## Web surface

- [ ] Asset responses carry the strict CSP from `app/public/_headers`: the browser network panel (after Access login) shows `Content-Security-Policy: default-src 'self'; script-src 'self'; ...` and `X-Frame-Options: DENY` on `/`.
- [ ] `/api/*` responses carry `Cache-Control: no-store` and `default-src 'none'` (`app/test/worker/routes/envelope.test.ts`); `/oauth/*` responses are `no-store` too (`app/src/worker/routes/oauth.ts`).
- [ ] CSRF tests pass: mutating `/api/*` without `X-Clearbox-CSRF: 1` gives `403 csrf_required` (`app/test/worker/csrf/csrf.test.ts`); no CORS headers anywhere.
- [ ] Email content is plain text only: `git grep -n "dangerouslySetInnerHTML\|innerHTML" -- app/src` returns nothing.

## Destructive actions

- [ ] Approval invariant tests pass: no provider call without a `pending` suggestion id in the request, cap 100 ids, idempotent repeats, `unsure` not approvable (`app/test/worker/actions/execute.test.ts`, `app/test/worker/routes/actions.test.ts`).
- [ ] No hard-delete code path: `git grep -n "batchDelete\|messages/.*/delete\|permanentDelete" -- packages app/src` returns nothing.
- [ ] Undo works within 24 hours on a real test mailbox for trash and archive batches (`app/test/worker/actions/undo.test.ts` covers the logic). Keep decisions are not undoable by design.

## Data minimization, residency and logs

- [ ] D1 is in the EU jurisdiction: `$CF d1 get <d1-id>` shows the jurisdiction `eu` (or the dashboard shows the EU location).
- [ ] Decision-1 deployment uses `DataZoneStandard` in `swedencentral`: `az cognitiveservices account deployment show --resource-group <resource-group> --name <foundry-account> --deployment-name decision-1 --query sku.name`.
- [ ] `observability.redactQueryString` is `true` in `app/cloudflare.config.ts`.
- [ ] Only `app/src/worker/log.ts` calls `console` in the Worker: `git grep -n "console\." -- app/src/worker ':!app/src/worker/log.ts'` returns nothing.
- [ ] A tail of real traffic (`npx wrangler tail clearbox`) shows no addresses, subjects, snippets, provider ids, tokens or URLs.
- [ ] DB isolation scan test passes (`app/test/worker/db-isolation.test.ts`).

## Repository settings

- [ ] Secret scanning and push protection enabled (see SECURITY.md for the `gh api` commands).
- [ ] Dependabot alerts and private vulnerability reporting enabled.
- [ ] Branch protection on `main` requires the CI and CodeQL checks.
